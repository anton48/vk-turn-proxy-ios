# vk-turn-proxy-console — консольный клиент

Тот же транспорт, что и в приложении (WireGuard поверх DTLS-SRTP поверх TURN-релеев VK до сервера с `-srtp`), для macOS, Linux и FreeBSD. По умолчанию весь трафик машины и её DNS идут через туннель, как в приложении на iPhone.

## Где взять

Бинарники прикладываются к каждому релизу рядом с `VKTurnProxy.ipa`:

| Файл | Система |
|---|---|
| `vk-turn-proxy-console-darwin-arm64` | macOS на Apple Silicon |
| `vk-turn-proxy-console-darwin-amd64` | macOS на Intel |
| `vk-turn-proxy-console-linux-amd64` | Linux x86-64 |
| `vk-turn-proxy-console-linux-arm64` | Linux ARM64 |
| `vk-turn-proxy-console-freebsd-amd64` | FreeBSD x86-64 |

Контрольные суммы лежат в `SHA256SUMS.txt`. Бинарники статические, установка не нужна:

```bash
chmod +x vk-turn-proxy-console-linux-amd64
```

macOS помечает скачанный браузером файл карантином, а бинарники не подписаны. Снимите пометку:

```bash
xattr -d com.apple.quarantine vk-turn-proxy-console-darwin-arm64
```

## Конфиг

Конфиг — полная резервная копия приложения: раздел **Backup & Restore**, кнопка **Export Full Backup…**. Положите её рядом под именем `vk-turn-proxy-console.json` или укажите путь через `-config`. В файле закрытый ключ WireGuard, поэтому закройте его от других пользователей:

```bash
chmod 600 vk-turn-proxy-console.json
```

Консоль берёт первый сервер режима SRTP. Другой сервер выбирается по имени через `-server`, список показывает `-list`. Серверы других режимов (WRAP-A, WRAP-S, csqtt) консоль не поддерживает. Кэш TURN-учёток из резервной копии не используется: у консоли свой кэш, `.vk-turn-proxy-console-creds.json` в рабочем каталоге. Снимок браузера телефона тоже не используется, отпечаток для капчи генерируется свой.

## Запуск

Нужны права root, потому что консоль создаёт туннельный интерфейс и меняет таблицу маршрутизации и DNS:

```bash
sudo ./vk-turn-proxy-console-linux-amd64
```

Что происходит при запуске:

1. Поднимаются соединения через релеи VK.
2. Создаётся туннельный интерфейс и проходит рукопожатие WireGuard.
3. Весь IPv4 уходит в туннель двумя маршрутами `0.0.0.0/1` и `128.0.0.0/1`. Сам маршрут по умолчанию не трогается.
4. Системный DNS переключается на серверы из настроек сервера (`dnsServers`).

Собственный трафик клиента (релеи, API VK, DNS сети) идёт мимо туннеля. Для каждого такого адреса при первом обращении ставится маршрут `/32` через физический шлюз, и `netstat -rn` его покажет. Адреса SSH-клиентов закрепляются так же, поэтому SSH-сессии переживают переключение. Консоль берёт их из таблицы соединений системы: это все установленные соединения на порт 22, потому что `sudo` не передаёт `$SSH_CLIENT`. Закрепляются клиенты по IPv4, а IPv6 и так идёт мимо туннеля.

Ctrl-C (или SIGTERM, SIGHUP) возвращает всё: DNS, маршруты, интерфейс. Каждое изменение до выполнения записывается в `.vk-turn-proxy-console-state.json` вместе с командой отмены. Если процесс упал, следующий запуск сначала всё вернёт. Можно вернуть и без запуска туннеля:

```bash
sudo ./vk-turn-proxy-console-linux-amd64 -cleanup
```

При смене сети (другой Wi-Fi, кабель, модем) закрепления переносятся на новый шлюз, а соединения перестраиваются, как в приложении. Пробуждение ноутбука после сна тоже замечается.

## Флаги

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `-config` | `vk-turn-proxy-console.json` | резервная копия приложения |
| `-server` | первый сервер SRTP | сервер по имени из резервной копии |
| `-list` | | показать серверы и выйти |
| `-peer host:port` | из сервера | другой адрес SRTP-слушателя сервера |
| `-conns N` | из сервера, иначе 30 | число соединений, от 1 до 120 |
| `-pool-reserve R` | 1 | запасные наборы учёток: пул (1 + R) × ceil(N/10) |
| `-turn-transport` | из сервера | `tcp` или `udp` до релея |
| `-mtu` | из резервной копии, иначе 1280 | MTU туннеля |
| `-dns` | `dnsServers` сервера | список DNS через запятую или `false`, чтобы не трогать системный DNS |
| `-uplink-pace` | из резервной копии | пейсер отправки, KiB/s на соединение, 0 выключает |
| `-vk-link` | из резервной копии | ссылка на звонок VK вместо списка из резервной копии |
| `-turn-server host:port` | из сервера | свой TURN-релей |
| `-default-route` | `true` | `false`: в туннель идут только подсеть туннеля и `-route` |
| `-default-route-wait` | `2s` | сколько ждать все соединения после рукопожатия перед переключением |
| `-block-ipv6` | `false` | направить IPv6 в туннель, где он отбрасывается. Туннель несёт только IPv4, без флага IPv6 идёт мимо. Приложение получает тишину, а не отказ, и переходит на IPv4 только по своему таймауту или через Happy Eyeballs. Если к машине открыта SSH-сессия по IPv6 из чужой сети, консоль с этим флагом не запустится: блокировка оборвала бы сессию |
| `-keep-hosts` | | адреса, которые остаются на физическом пути |
| `-route` | | при `-default-route=false`: адреса, которые идут в туннель |
| `-vk-cookie-file` | | вход в VK из `cookies.txt` |
| `-cred-cache` | `.vk-turn-proxy-console-creds.json` | кэш учёток консоли |
| `-state-file` | `.vk-turn-proxy-console-state.json` | журнал изменений с отменой |
| `-cleanup` | | вернуть изменения упавшего запуска и выйти |
| `-gomaxprocs N` | все ядра | потоки планировщика Go |
| `-stats-every` | `30s` | интервал строки статистики, 0 выключает |
| `-tun-name` | `vktp0`, на macOS `utun` | имя туннельного интерфейса |
| `-keepalive` | 25 | persistent keepalive WireGuard, секунды |
| `-version` | | версия |

## Вход в VK

Если в приложении включён вход в VK (`vkAuth`), консоли нужен тот же вход. Экспортируйте cookies браузера, в котором вы вошли в VK, в формате Netscape `cookies.txt`, например расширением «Get cookies.txt». Затем передайте файл:

```bash
sudo ./vk-turn-proxy-console-darwin-arm64 -vk-cookie-file cookies.txt
```

Нужны два cookie, как в приложении: `remixsid` домена vk.com или vk.ru и `p` домена login.vk.com или login.vk.ru. В режиме входа используются все ссылки на звонки из резервной копии, по два релея на ссылку и до 20 соединений на ссылку.

## Капча

WebView в консоли нет. Учётки добываются тем же путём, что и в приложении, включая автоматический решатель капчи. Если VK всё-таки просит капчу, которую решатель не проходит, консоль пишет об этом и повторяет запрос каждые две минуты (десять при ограничении частоты).

## На сервере

Сервер должен работать с `-srtp`, а в его WireGuard должен быть peer с публичным ключом из этой резервной копии. Если рукопожатие не проходит 30 секунд, консоль напишет об этом и продолжит ждать.
